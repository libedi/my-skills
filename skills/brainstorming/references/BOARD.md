# 보드

질문을 브라우저 화면으로 보여주고 답을 받는 **선택적 표시 방식**이다. 진행 판단, 질문 선정, 기록은 [SKILL.md](../SKILL.md)를 그대로 따른다. 보드는 질문을 내보내고 답을 받는 통로만 바꾼다.

구성은 두 파일이다.

- [board.mjs](../scripts/board.mjs): Node 18 이상의 내장 모듈만 쓰는 임시 서버와 CLI
- [board.html](../assets/board.html): 외부 리소스 없는 단일 화면

## 원칙

1. **보드는 판단하지 않는다.** 다음 질문, 단계 이동, 통로 선택은 에이전트가 정한다. 화면과 서버에 분기나 단계 로직을 넣지 않는다. 판단 주체가 둘이 되면 화면과 대화가 어긋난다.
2. **보드는 상태를 저장하지 않는다.** 서버는 지금 라운드 하나만 메모리에 들고 파일을 남기지 않는다. 논의 상태의 원본은 대화(작업 노트를 쓰면 노트) 하나뿐이다.
3. **프롬프트가 기본이다.** 보드를 쓸 수 없으면 묻지 않고 프롬프트로 진행한다. 보드가 망가져도 skill은 그대로 동작해야 한다.
4. **정보는 같고 형식만 다르다.** 보드는 프롬프트보다 더 보여주지도, 덜 보여주지도 않는다. 단계, 진행률, 축 현황, 예산 같은 관리 상태는 화면에 꺼내지 않는다.
5. **임시 도구다.** 브레인스토밍이 끝나면 끈다. 팀 공유 서버 같은 다른 서버와 섞지 않는다.

## 시작

- 브라우저 탭이 열리므로 처음 한 번 제안하고 동의를 받는다. 거절하면 사용자가 다시 꺼내기 전까지 제안하지 않는다.
- Node 18 이상이 없거나, `start`가 실패하거나, 사용자가 브라우저를 볼 수 없는 환경(원격 세션, 클라우드 실행, CI)이면 제안하지 않고 프롬프트로 진행한다.
- 동의하면 서버를 띄운다. 출력된 `url`(토큰 포함)을 대화 내내 쓰고, 브라우저가 열리지 않았을 때를 위해 채팅에도 남긴다.

```
node <skill>/scripts/board.mjs start --open
→ {"status": "started", "url": "http://127.0.0.1:52341/?t=…", "pid": 1234}
node <skill>/scripts/board.mjs status '<url>'
```

`start` 직후 `status`로 서버가 살아 있는지 한 번 확인한다. `not-running`이면 § 셸 호환의 포그라운드 실행을 따른다.

## 라운드마다 통로 고르기

- 기본은 지금 쓰는 통로에 머문다. 화면을 오가는 비용이 질문 하나보다 크다.
- 질문의 성격이 다른 통로를 필요로 할 때만 바꾼다. 길게 생각해 써야 하는 열린 질문, 스펙 도구 진입처럼 채팅이 필요한 일은 채팅으로 간다. 확인, 선택, 예시 표, 분류, 관점 반응처럼 닫힌 항목이 이어지면 보드로 간다.
- **보드 → 채팅**: 에이전트가 바꿀 때는 먼저 넘김 화면을 띄운다. 사용자는 보드를 보며 기다리고 있으므로, 화면에서 알리지 않은 채 채팅에서 묻지 않는다.

  ```
  node <skill>/scripts/board.mjs handoff '<url>' --reason "다음은 열린 질문이라 채팅이 편해요" --next "이 기능이 지금 필요한 이유는?"
  ```
- **채팅 → 보드**: 채팅에 "보드에서 이어갈게요"와 `url`을 남긴 뒤 `ask`한다.
- 사용자가 "채팅에서 계속하기"를 누른 경우는 본인이 고른 전환이므로 넘김 화면이 필요 없다.

## 묻고 받기

라운드를 JSON 파일로 쓰고 `ask`를 실행한다. 보드에 표시되고, 사용자가 제출할 때까지 명령이 기다렸다가 답을 `--out` 파일에 쓴다. 명령 출력은 `status`, `round`, `written`만 담은 한 줄이고, 답 전체는 파일 도구로 읽는다. 셸과 콘솔 인코딩에 상관없이 같은 방식으로 동작하므로 모든 환경에서 이 방식을 쓴다(§ 셸 호환).

```
node <skill>/scripts/board.mjs ask '<url>' .brainstorm/board-round.json --timeout 540 --out .brainstorm/board-answer.json
node <skill>/scripts/board.mjs wait '<url>' --round r3 --timeout 540 --out .brainstorm/board-answer.json
```

- 라운드 파일과 답 파일은 라운드마다 덮어쓰는 임시 파일이다. 작업 노트와 같은 `.brainstorm/` 아래 두면 gitignore가 이미 되어 있다. 이 파일들은 보드의 상태가 아니며, 다음 라운드를 정하는 근거는 언제나 대화(또는 작업 노트)다.
- 셸 도구의 시간 제한은 `--timeout`보다 길게 잡는다. 셸 명령에 최대 시간이 있는 런타임이면 `--timeout`을 그보다 짧게 준다.

| status | 뜻 | 할 일 |
|---|---|---|
| `answered` | 제출됨 | 답을 반영하고 다음 라운드를 정한다 |
| `exit` | 사용자가 "채팅에서 계속하기"를 누름 | 받은 답은 반영하고 `pending` 항목만 채팅에서 이어 묻는다. 이유를 묻지 않는다 |
| `timeout` | 아직 답이 없음 | `wait`로 다시 기다린다. 사용자에게 알리지 않는다 |
| `cancelled`, `stale` | 다른 라운드로 바뀜 | 최신 라운드 기준으로 다시 판단한다 |
| `stopped`, `error` | 서버가 꺼졌거나 닿지 않음 | `start`를 한 번 다시 시도하고, 안 되면 프롬프트로 진행한다 |

- 오래 답이 없으면(예: `timeout` 연속 3번) 기다리기를 멈추고, 채팅에 "보드에 질문을 남겨뒀어요. 답하셨으면 알려주세요"라고 남긴 뒤 턴을 끝낸다. 그동안 보드는 "에이전트가 기다리고 있지 않아요"로 잠기고 적어둔 내용은 남는다. 사용자가 돌아오면 같은 라운드 ID로 `wait`한다.

## 셸 호환

에이전트는 자기가 어느 셸(bash, zsh, Windows PowerShell 5.1, Git Bash 등)에서 명령을 내리는지 몰라도 된다. 아래 형태만 쓰면 어느 셸에서든 같게 동작한다.

- **한 줄에 명령 하나.** `&&`로 잇지 않는다. Windows PowerShell 5.1에는 `&&`가 없다.
- **URL은 작은따옴표로 감싼다.** 모든 셸에서 그대로 전달된다.
- **라운드 JSON은 파일 쓰기 도구로 UTF-8 파일에 쓴다.** 셸 리다이렉션(`>`, `Out-File`, `Set-Content`)이나 파이프로 만들지 않는다. PowerShell 5.1은 기본으로 UTF-16이나 시스템 코드 페이지로 써서 한글이 깨진다. `board.mjs`는 UTF-8(BOM 포함)과 UTF-16 BOM 파일을 읽고, 그 밖의 인코딩은 거절한다.
- **답은 `--out` 파일로 받아 파일 도구로 읽는다.** PowerShell 5.1은 명령 출력을 시스템 코드 페이지(한국어 Windows는 cp949)로 읽어서 UTF-8 한글이 깨진다. `--out` 없이 실행해도 Windows에서는 한글을 `\uXXXX`로 이스케이프해 손실은 없지만 읽기 어렵다. Git Bash(`MSYSTEM`이 있는 셸)에서는 이스케이프하지 않는다. `--ascii`, `--utf8`로 강제할 수 있다.
- **경로는 작업 폴더 기준 상대 경로.** Git Bash가 `/c/...` 같은 절대 경로를 바꿔 넘기는 일을 피한다.
- **`--reason`, `--next` 문구에 큰따옴표를 넣지 않는다.** 셸마다 따옴표 이스케이프 규칙이 다르다.
- **서버가 바로 꺼지면 포그라운드로 띄운다.** 명령이 끝날 때 셸이나 런타임이 백그라운드 프로세스까지 정리하는 환경이면 `start` 직후 `status`가 `not-running`이다. 이때는 사용자에게 별도 터미널에서 `node <skill>/scripts/board.mjs start --foreground --open`을 실행해 달라고 하고, 출력된 `url`을 받는다.

## 라운드 구성

- 한 라운드에는 서로 독립적인 항목만 넣는다. 앞 답에 따라 달라지는 질문은 다음 라운드로 넘긴다. 왕복 비용이 작으므로 항목 하나짜리 라운드도 괜찮다.
- 항목 ID는 대화 내내 바꾸지 않고 요구사항·AC 번호와 맞춘다(`R2.Q1`, `R2.EX3`). 지난 결정을 다시 열 때 그 ID로 가리킨다.
- 추천안은 `recommended`로 표시만 하고 미리 선택하지 않는다. 선택 질문에는 언제나 "다른 답"과 메모가 있다.
- `[가정]` 항목은 `assumption` 척도(확인된 사실 / 일단 진행 / 아님)로 묻는다. 맞음/아님으로 물으면 사실 확인인지 일단 진행인지 구분되지 않는다.
- 맥락은 질문 안에 둔다(`note`, `context`). 앞 결정이 필요한 질문만 그 결정을 언급한다.
- `history`에는 사용자가 답한 내용을 그대로 넣는다. 확정 표시, 개수, 상태는 넣지 않는다. 화면에서는 "지난 답"으로 접혀 있고, `id`가 있는 항목은 "다시 보기"로 다시 열 수 있다.
- 요약은 프롬프트와 같은 때에만 보낸다(정리 단계 확인, 이어하기, 게이트). 요약도 한 라운드로 보낸다.
- 결정을 다시 여는 라운드에서는 그 결정에 기대는 항목도 함께 다시 봐야 한다고 그 질문 안에서 알린다.

## 항목 유형

질문 유형은 통로와 상관없이 같다. 보드에서 쓸 수 없을 때를 위해 프롬프트 표현을 함께 둔다.

| type | 쓰임 | 보드 | 프롬프트에서는 |
|---|---|---|---|
| `rate` | 추정 확인, 가정 확인, 관점 반응, 시나리오 판정 | 척도 버튼 (`confirm`, `assumption`, `react`, `judge`, 또는 직접 정의) | 번호 목록, "1 맞음, 3 아님"처럼 짧게 답 |
| `choose` | 결정 질문 | 선택지 카드와 "다른 답" | 선택지와 추천 이유를 쓰고 번호로 답 |
| `table` | 예시 표의 `???` 칸 | 표와 칸별 선택지 | 표를 쓰고 `???` 칸만 묻기 |
| `bucket` | A~D 분류 조정 | 항목별 버킷 버튼 | 분류 목록, "b2→A"처럼 옮길 것만 답 |
| `spectrum` | 말로 꺼내기 어려운 위치 | 슬라이더 | 0~10 숫자, 양 끝 설명 |
| `text` (`gate`) | 보기 전에 자기 말 먼저 | 적거나 건너뛰어야 아래 항목이 펼쳐짐 | 첫 턴에 열린 질문, 보기는 다음 턴 |

### 라운드 예시

```json
{
  "title": "정산 배치 · 취소 주문 반영",
  "context": ["SettlementJob과 주문 테이블을 확인했어요."],
  "history": [{ "id": "R1.Q0", "q": "정산 대상 범위", "a": "전일 주문 전체" }],
  "items": [
    { "id": "R1.A1", "type": "rate", "scale": "confirm", "section": "코드에서 추정한 것",
      "tag": "코드에서 추정", "text": "취소 여부는 STATUS = 'CANCELED'로 판단", "note": "근거: OrderReader 쿼리" },
    { "id": "R1.A3", "type": "rate", "scale": "assumption", "tag": "가정",
      "text": "정산 후 들어온 취소는 다음 날 차감", "note": "근거 없음 · 운영팀 확인 필요" },
    { "id": "R2.Q1", "type": "choose", "section": "결정 질문", "text": "부분취소 주문은 어떻게 정산할까요?",
      "options": [
        { "v": "a", "label": "잔액 기준", "desc": "3,000 − 1,000 → 2,000", "recommended": true },
        { "v": "b", "label": "전부 제외", "desc": "남은 매출이 빠짐" } ] },
    { "id": "R2.EX", "type": "table", "text": "??? 칸만 채워주세요", "columns": ["상황", "주문", "정산"],
      "rows": [
        ["완료", "10,000", "10,000"],
        ["누적 부분취소가 전액", "3,000",
          { "ask": "R2.EX3", "options": [ { "v": "a", "label": "제외", "recommended": true },
                                          { "v": "b", "label": "0원 행", "short": "0" } ] } ] ] },
    { "id": "R2.BK", "type": "bucket", "text": "틀린 분류만 옮겨주세요",
      "buckets": { "A": "핵심 AC", "B": "테스트 후보", "C": "횡단 관심사", "D": "구현 세부" },
      "budget": { "A": 7 },
      "entries": [ { "id": "a1", "text": "부분취소는 잔액으로 정산한다", "bucket": "A", "note": "추천 수용" } ] }
  ]
}
```

- 공통: `id`, `type`, `text`, `note`(근거·맥락), `tag`(출처 태그 표시), `section`(구역 제목), `required`(기본: `rate`·`choose`·표 칸은 필수, 나머지는 선택)
- `rate`: `scale`(기본 `confirm`) 또는 `[{ "v", "label" }]`, `memoOn`(메모 칸을 여는 값)
- `choose`와 표 칸: `options[{ v, label, desc, recommended, short }]`, `other: false`로 "다른 답" 숨김, `otherLabel`
- `spectrum`: `left`, `right`, `min`, `max`, `step`
- `text`: `gate`(라운드에 하나), `skippable`, `placeholder`

## 답 형식

```json
{
  "status": "answered",
  "round": "r3",
  "answers": {
    "R1.A1": { "value": "no", "memo": "STATUS 말고 취소 플래그" },
    "R1.A3": { "value": "assume" },
    "R2.Q1": { "value": "a" },
    "R2.EX3": { "value": "other", "memo": "0원 행으로 남기되 리포트에서 숨김" },
    "R2.BK": { "moves": [ { "id": "b1", "from": "B", "to": "A" } ] },
    "T.OWN": { "value": "처음 적은 말", "edited": "보기를 본 뒤 고친 말" }
  },
  "pending": ["R2.SP"],
  "reopen": [ { "id": "R1.Q0", "memo": "범위가 바뀌었어요" } ],
  "memo": "부분취소 쿠폰 회수 규칙도 있어요"
}
```

`gate` 텍스트를 건너뛰면 `{ "skipped": true }`다. `edited`가 있으면 보기를 본 뒤 고친 것이다. 둘 다 읽되, 생각이 정리된 것인지 보기에 끌려간 것인지 구분해서 본다.

## 답 반영

결정을 기록하는 곳(작업 노트를 쓰면 노트)에 아래 태그로 옮긴다.

| 보드에서 | 기록 |
|---|---|
| 추천안을 그대로 고름 | `[추천 수용]` |
| 다른 선택지나 "다른 답"으로 정함 | `[사용자 확정]` |
| 추정 항목에 "맞음", 가정 항목에 "확인된 사실" | `[사용자 확정]` |
| 가정 항목에 "일단 진행" | `[가정]` 유지, "확인 필요"에 확인할 곳이나 사람 |
| "아님"과 메모 | 메모 내용으로 고치고, 기존 이해가 바뀌면 탐색으로 돌아간다 |
| `reopen` | 그 결정을 다시 열고 어디로 돌아갈지 § 진행 판단으로 정한다 |
| `pending` | 다음 라운드나 채팅에서 다시 묻는다 |
| `memo` | 새 정보로 읽는다. 기존 이해를 바꾸면 탐색으로 돌아간다 |

## 끝내기

- § 마무리에서 브레인스토밍을 끝내면 서버를 끄고(`node board.mjs stop '<url>'`) 라운드·답 임시 파일을 지운다.
- 에이전트의 요청이 없는 채로 30분이 지나면 서버는 스스로 꺼진다(`start --idle-minutes`로 조정).
- 사용자가 탭을 닫아도 같은 `url`을 다시 열면 지금 질문이 그대로 나온다.

## 보안

서버는 127.0.0.1에서만 듣고, `url`의 토큰이 없으면 응답하지 않는다. `url`을 다른 사람과 공유하지 않는다.
